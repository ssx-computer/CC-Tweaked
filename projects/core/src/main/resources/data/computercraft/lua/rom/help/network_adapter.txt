The "network_adapter" block connects a ComputerCraft network to an Applied Energistics 2 ME
network. Attach a CC cable to the front and an AE2 cable to the back. It needs Applied
Energistics 2 installed.

When the adapter is joined to an active ME network it appears on the CC network as a
"network_adapter" peripheral (named "me<location>"), which you can wrap with
peripheral.wrap(). It gives a computer read/write access to the ME network's storage.

Methods:

  isConnected()
    Whether the adapter currently has an active ME network to talk to.

  getItems()
    Returns a list of every stack stored in the ME network, as
    { name, display, count, type, amountPerUnit } tables. The "name" is the Minecraft item
    id, such as "minecraft:cobblestone", which you can use with pushItem()/extractItem().

  getCells()
    Returns a list of every storage cell in ME drives and ME chests on the network, as
    { slot, name, display, status, location } tables.

  getPower()
    Returns the ME network's power state as
    { stored, max, avgUsage, idlePower, channelPower, powered }.

  getCraftable()
    Returns a list of every item the ME network can craft, as
    { name, display, count, type } tables.

  pushItem(name, count)
    Store "count" of the given item (by id, e.g. "minecraft:cobblestone") into the ME
    network. Returns the number actually stored.

  extractItem(name, count)
    Pull "count" of the given item out of the ME network. Returns the number actually
    extracted.

  addAuthKey(key, [items])
    Register a key that may write to the given item ids (or to every item, if "items" is
    omitted). Returns whether the key already existed. See "Authentication" below.

  removeAuthKey(key)
    Remove a key's write permissions. Returns whether the key existed.

  listAuth()
    Returns a map of each key to the list of item ids it may write to.

Example: print("stored", peripheral.wrap("me0").getItems())

Authentication
--------------

An adapter can protect its ME storage with keys. Until any key is configured, writes are
allowed directly, exactly as without authentication. Once you register a key with
addAuthKey(), the adapter is locked: pushItem() and extractItem() only work if the request
carries a key which is registered for that item. Read-only methods (getItems, getCells,
getPower, getCraftable) never require a key.

Accessing ME over the virtual network
------------------------------------

An adapter is also a host on CC's virtual network. It joins it when it has an active ME
network, and serves the same methods over a UDP socket, so a computer can read and write ME
storage through a network_core without a wired connection to the adapter.

The easiest way is the "cc.me" module, which opens a socket for you, sends a request, and
returns the reply. It broadcasts to find an adapter:

    local me = require("cc.me")
    print(me.getItems())
    me.pushItem({ name = "minecraft:cobblestone", count = 64, key = "my-key" })

You can manage keys over the virtual network too:

    me.addAuthKey("my-key", { "minecraft:cobblestone" })
    me.listAuth()
    me.removeAuthKey("my-key")

Each method takes a table of extra arguments and an optional adapter address. To talk to a
specific adapter, pass its virtual-network address: me.getItems({}, "10.0.0.5").

If you would rather use the raw "net" API: listen on port 19781 (the ASCII "ME"), send a
JSON request broadcast to 255.255.255.255, and drain the reply:

    local socket = net.listen(19781)
    net.send("255.255.255.255", 19781, textutils.serializeJSON({ id = "1", op = "getPower" }), socket)

A request is a JSON object with an "op" and an optional "id". The reply is
{"ok":true,"id":...,"result":...} on success, or {"ok":false,"error":"..."} on failure.

The valid operations are isConnected, getItems, getCells, getPower, getCraftable, pushItem
(pass "name", "count" and optionally "key"), extractItem (pass "name", "count" and
optionally "key"), addAuthKey (pass "key" and optionally "items"), removeAuthKey (pass
"key") and listAuth.
